# FastDrop — developer documentation

## 1. Architecture

```
 Android app (Kotlin)                                   PC app (Go, single exe)
 ┌───────────────────────┐   Wi-Fi  TCP :8765          ┌──────────────────────────┐
 │ MainActivity (UI)     │◄───────────────────────────►│ HTTP server  (:8765)     │
 │ Engine (all logic)    │   USB    adb reverse        │  /up /file /bench /api/* │
 │ TransferService (FGS) │◄───────────────────────────►│ UDP beacon   (:8766)     │
 │ ShareActivity         │   UDP broadcast :8766       │ usbLoop (adb reverse)    │
 └───────────────────────┘                             │ embedded web UI (window) │
                                                       └──────────────────────────┘
```

* The **PC is the server**; the phone is always the client (it polls, uploads, downloads).
* The PC UI is a single embedded `index.html` shown in an Edge/Chrome `--app=` window (falls back to the default browser).
* Both directions use **plain HTTP/1.1 over TCP, no TLS, no compression** — the fastest simple option on a trusted LAN.

### Source layout

| Path | Role |
|---|---|
| `windows/main.go` | HTTP server, inbox/outbox state, beacon, `/api/*`, bench, QR, reveal |
| `windows/usb.go`, `usb_windows.go`, `usb_other.go` | keeps `adb reverse tcp:8765 tcp:8765` alive; hides the console window on Windows |
| `windows/reveal_windows.go`, `reveal_other.go` | "show in folder" (Explorer `/select,` / `xdg-open`) |

| `android/.../SpeedView.kt` | animated speed gauge (custom `View`) |
| `android/.../TransferService.kt` | foreground service + Wi-Fi low-latency lock + wake lock; self-stops when idle |
| `android/.../ShareActivity.kt` | Android share-sheet target ("Share → FastDrop") |

## 2. Protocol

### 2.1 Discovery
* **UDP beacon**: the PC broadcasts `FASTDROP1|<hostname>|<port>` to every interface's subnet broadcast on UDP **8766** once a second and answers the probe `FASTDROP?`.
* The phone listens on 8766 (holds a `MulticastLock`), also broadcasts `FASTDROP?` while disconnected, and adopts the source address of the first beacon it hears if it is not connected.
* **QR / deep link**: `fastdrop://connect?name=<host>&port=8765&ip=<a>&ip=<b>…` (generated by `/api/qr`). The phone probes every `ip` in parallel (`GET /api/state`, 1.5 s timeout) and keeps the lowest-latency responder. The same URI works as an Android deep link (`adb shell am start -a android.intent.action.VIEW -d 'fastdrop://connect?…'`), so any QR scanner app can open it.
* Virtual adapters (docker, VM, bridges) are excluded from the advertised addresses.

### 2.2 Endpoints (PC, port 8765)

| Method / path | Purpose |
|---|---|
| `GET /api/state[?dev=<name>]` | JSON: host name, IPs, inbox, outbox, `phone`, `wifi`, `usb`, `usbState`, bench counter. `dev=` marks the caller as the phone. |
| `PUT /up?id&name&size&off` | One byte-range **chunk** of a phone→PC file. First chunk of an `id` creates + pre-sizes the file; chunks are written with `WriteAt`; the file completes when received bytes ≥ `size`. |
| `GET /file/<id>` | PC→phone file with `Range` support (`http.ServeContent`). |
| `POST /api/outbox?name` | Streams a dropped file into the PC's temp outbox (the phone then pulls it). |
| `POST /api/clear?kind=inbox|outbox[&id]` | Clear list / remove an item. |
| `POST /api/reveal?id` | Select a received file in the file manager. |
| `GET /api/qr` | PNG QR code (see 2.1). |
| `PUT /bench/up`, `GET /bench/down` | Throughput probes (discard / endless stream) for the speed test. |
| `POST /api/open`, `/api/quit` | Open received folder; quit. |

### 2.3 How a transfer is made fast
* **Chunking + work stealing**: files are cut into **8 MB chunks**; N worker threads each take the next chunk index from an atomic counter, so faster links automatically carry more chunks.
* **Parallel TCP**: default **4 streams per link** (the speed test picks 1/2/4/8; > 4 caused packet loss on this Wi-Fi).
* **Multipath**: worker *i* uses path `paths[i % paths.size]`; paths = Wi-Fi host and, when reachable, `127.0.0.1` (the USB tunnel). Mode `BOTH / WIFI / CABLE` selects the list.
* **Raw sockets** on Android: keep-alive HTTP/1.1 written by hand, 4 MB send/receive buffers set *before* connect, `TCP_NODELAY`, 1 MB I/O buffers, positional `FileChannel` reads/writes (no memory buffering, any file size).
* **Phone radio**: foreground service + `WIFI_MODE_FULL_LOW_LATENCY` lock + partial wake lock while in use.
* Downloads are written through `MediaStore.Downloads` (`Download/FastDrop`, `IS_PENDING` until complete).
* Retries: each chunk retries up to 3× on a fresh connection; non-seekable sources (single stream) are not retried.

### 2.4 Cable (USB) path
`usb.go` runs `adb reverse tcp:8765 tcp:8765` every few seconds (needs `adb` on `PATH` or next to the exe and a phone with USB debugging that has authorized this PC). The phone then reaches the PC at `127.0.0.1:8765` over USB. The phone probes that address every ~3 s (`probeUsb`, must report the same PC name); requests arriving from a loopback address mark the cable as active on the PC (`usb` in `/api/state`), others mark Wi-Fi.

## 3. Build

### PC (cross-compiled from Linux or built on Windows)
```bash
cd windows
GOOS=windows GOARCH=amd64 go build -trimpath -ldflags "-s -w -H windowsgui" -o FastDrop.exe .   # no console window
go build -o fastdrop-linux .                                                                      # Linux test build
```
Go ≥ 1.22. One dependency: `github.com/skip2/go-qrcode`. `-H windowsgui` hides the console; the exe is unsigned.

### Phone
```bash
cd android
./gradlew assembleRelease        # app/build/outputs/apk/release/app-release.apk (debug-signed)
adb install -r app/build/outputs/apk/release/app-release.apk
```
JDK 17, Android SDK 36, AGP 8.12, Kotlin 2.2.10. `minSdk 29`, `targetSdk 35`. Needs network once for `play-services-code-scanner` (QR scanning UI, no camera permission needed).

### Package for the Windows laptop
`dist/` = `FastDrop.exe`, `FastDrop.apk`, `Install-FastDrop.bat` (copy + firewall + shortcut), `README.txt`; zipped as `FastDrop-Windows-Package.zip`.

## 5. Research notes & decisions

* **Compression** (zstd/lz4) only helps compressible files; photos, video, zip, APK are already compressed. Not implemented; planned design: sample 1 MB, compress only if > ~15 % smaller, skip media extensions (lz4/zstd-1 are far faster than the link).
* **Custom UDP / QUIC protocol**: published results show gains under packet loss, not on a clean link. At ~70 MB/s with a few retransmits, multi-stream TCP + multipath gives more than a new protocol; revisit only if measured loss is high.
* **Bluetooth** is ~0.15 MB/s (BLE 2M) — about 500× slower; not worth using even for discovery.
* **Wi-Fi hairpin**: phone→router→PC uses airtime twice; a direct link (hotspot / Wi-Fi Direct) should be faster. A phone-hosted `LocalOnlyHotspot` ("Turbo link") was built and **removed**: on the OnePlus 15R it broke the Wi-Fi link (PC→phone packets stopped) while active.
* **Android 17** requires the `ACCESS_LOCAL_NETWORK` runtime permission for apps targeting API 37; FastDrop targets 35. Add it before raising the target.
* **Encryption** is off on purpose (user requirement); other apps measured 2–5× slower with it on.

## 6. Bugs found & fixed (history)

| Bug | Cause | Fix |
|---|---|---|
| Phone always "Looking for PC", auto-receive never worked | Android blocks cleartext HTTP for `HttpURLConnection` (targetSdk ≥ 28) | `usesCleartextTraffic="true"` |
| 17 MB/s file sends, connection stalls | Turbo hotspot active; PC→phone packets dropped | feature removed |
| 8 streams chosen from a cable-only test | cable upload over-counted by socket buffering | streams are now per link, default 4, pref reset |
| QR window closed itself while connected | UI hid it on every poll | hide only on the not-connected→connected transition |
| Blank phone UI after an edit | refresh loop/lifecycle code deleted by a bad patch | restored `onStart/onStop/tick` |

## 7. Known limitations / future work

* No encryption or pairing — anyone on the LAN can use the endpoints while the app runs.
* Cable mode needs `adb` on the PC and USB debugging on the phone; `adb` cannot be bundled (licence).
* The exe is unsigned (SmartScreen warning); the APK is debug-signed (Play Protect may warn).
* No resume after the app is killed mid-file; no folder transfer (select files).
* Ideas: adaptive zstd for compressible files, tray icon / auto-start, signed builds, UDP mode if loss is measured, USB 3 speed test, Wi-Fi Direct.
